\subsection{Checklists}
\entry{Interactive}\label{interactivecheck}
{\footnotesize\tightdisplay
\topic{Protocol}
\begin{checks}
	\item Flush after every line, with \texttt{endl} or \texttt{cout.flush()}.
	\item After \texttt{cin.tie(nullptr)}, reading no longer flushes \texttt{cout}.
	\item Exit at once after the final answer, and when the judge answers $-1$.
	\item Read with \texttt{cin}, never with Fast IO (\S\ref{fastio}): it waits for a full buffer.
	\item Count the queries against the limit, also in the worst case.
\end{checks}
\topic{Randomness}
Seed a randomised strategy from the clock (\texttt{randomize} in the template).
An adaptive judge can be tuned against a constant seed, because it then knows every query in advance.
\topic{Query bound}
Use this to check whether a strategy can fit the query limit at all.
\[ q \ge \left\lceil \log_r N \right\rceil \]
Here $N$ is the number of possible answers and $r$ the number of possible responses to one query.
Example: $N = 10^6$ with yes/no queries needs $q \ge 20$.
\topic{One lie}
Use this when the judge may give one wrong yes/no response; $n$ candidates and $q$ adaptive queries.
\[ n(q + 1) \le 2^q \]
This is needed for any queries. It is enough for even $n$ when a query may ask about any subset; with comparison queries it is necessary but may not be enough. For odd $n$ and subset queries the exact condition is
\[ n(q + 1) + q - 1 \le 2^q. \]
Example: $n = 10^6$ needs 25 queries instead of 20; $n = 3$ needs 5.
\topic{Local run}
Use a named pipe to connect the solution to your own interactor.
\begin{facts}
	\item By hand: \texttt{mkfifo f; (./sol < f) | (./interactor > f)}. The interactor's \texttt{cerr} shows the dialogue if it logs it.
	\item Many seeds: \texttt{./stress.sh sol -m inter} (\S\ref{stress}).
\end{facts}
}
\entry{Multi-pass}\label{multipasscheck}
{\footnotesize\tightdisplay
\topic{Checklist}
Use it when the program runs twice and pass 2 reads what pass 1 wrote.
\begin{checks}
	\item Tell the passes apart by the first input token.
	\item Use a fixed seed, \texttt{mt19937\_64 rng(12\cppsep345)}, not \texttt{randomize}: both passes must make the same choices.
	\item Iterate in a canonical order. Never iterate an \texttt{unordered\_map} or \texttt{unordered\_set}, never sort by pointer.
	\item Fix the hash base: in Rolling hash (\S\ref{strhash}) replace the random \texttt{B} by a constant such as \texttt{911\cppsep382\cppsep323}.
	\item The time limit holds for each pass separately.
	\item Nothing carries over between passes: no files, no memory.
	\item Test with \texttt{./stress.sh p -m multi -c chk} and a \texttt{noise.cpp} that plays the judge (\S\ref{stress}).
\end{checks}
}

\subsection{Codes}
\entry{Linear codes: Reed--Solomon, GF(2), stuck bits}\label{linearcodes}
{\footnotesize\tightdisplay
\topic{Reed--Solomon: erased symbols}
Use it when symbols may be lost but the positions of the survivors are known.
\begin{facts}
	\item Pick a prime $n \le p < 2^{30}$ (the \texttt{Mint} limit) and $n$ distinct nodes $\alpha_i$, e.g. $\alpha_i = i$. The message is $k$ symbols $m_0..m_{k-1}$ in $\mathbb{F}_p$.
	\item Send the values of the message polynomial at all nodes:
	\[ c_i = \sum_{j=0}^{k-1} m_j \alpha_i^j. \]
	\item Decode from any $k$ survivors with \texttt{interpolate(x, y)} (\S\ref{lagrange}): \texttt{x} holds their nodes, \texttt{y} their values, and the result is $m$.
	\item Passing all $s$ survivors also checks them: if 1 to $s - k$ of them are wrong, an entry of the result after index $k - 1$ is nonzero.
	\item Never call \texttt{interpolateAt} here: it needs the nodes $0..n-1$ in order.
\end{facts}
The minimum distance is
\[ d = n - k + 1, \]
so $e$ wrong and $s$ erased symbols can be corrected when
\[ 2e + s \le n - k. \]
This recipe corrects only $e = 0$.
Example over $\mathbb{F}_7$: $f(t) = 2 + 3t$ sends $2, 5, 1, 4$ at $t = 0..3$; the survivors $(1, 5), (3, 4)$ give back $2, 3$.
\topic{Random GF(2) code: erased bits}
Use it when bits may be lost, their positions are known, and a tiny failure probability is fine.
\begin{facts}
	\item Both sides build the same random $n \times k$ bit matrix $G$ from a fixed seed. Send the $n$ bits
	\[ c = G m \pmod 2. \]
	\item Decode with \texttt{solveXor(a, b, k)} (\S\ref{gauss}) on the surviving rows of $G$ and bits of $c$. Accept only \texttt{sz(s) == 1}, a unique solution; $k \le 4\dsep096$ fits \texttt{BitRow}.
	\item Let $S$ be the set of surviving rows. When the erasures do not depend on $G$,
	\[ \Pr[\operatorname{rank} G_S < k] \le (2^k - 1)\, 2^{-|S|} < 2^{-t} \quad \text{for } |S| = k + t. \]
	\item No solution means a bit is wrong, not only lost: the noise is not erasures.
\end{facts}
Example: rows $10, 01, 11$ send the message $10$ as $101$; any two rows decode it.
\topic{Stuck bits: store the syndrome}
Use it when the writer knows which cells are stuck and at which value, and the reader does not.
\begin{facts}
	\item Both sides build the same random $k \times n$ bit matrix $H$ from a fixed seed. The reader decodes the $k$-bit message as
	\[ m = H x \pmod 2. \]
	\item The writer splits the cells into the stuck set $S$, with values $b$, and the free set $F$; $F$ must be fixed independently of $H$. It solves, with \texttt{solveXor} (\S\ref{gauss}; needs $|F| \le 4\dsep096$, the \texttt{BitRow} limit),
	\[ H_F\, x_F = m + H_S\, b \pmod 2. \]
	\item Any solution works, so a kernel is no problem. No solution means the message cannot be written.
	\item If $|F| = k + t$, every message can be written except with probability below $2^{-t}$. So about $n - |S|$ bits fit.
\end{facts}
Example: $H = (1, 1, 1)$, first cell stuck at 1, message 0: write $110$.
}
\entry{Bit-level codes: self-delimiting, VT, pairs, checksum}\label{bitcodes}
{\footnotesize\tightdisplay
\topic{Unary}
Use it for small nonnegative integers, such as run lengths.
\begin{facts}
	\item Write $v$ ones, then a zero: $v + 1$ bits. Example: 0 is \texttt{0}, 3 is \texttt{1110}.
	\item Decode by counting ones up to the first zero. A missing zero means the input was cut.
\end{facts}
\topic{Elias-gamma}
Use it for positive integers of very different sizes.
\begin{facts}
	\item For $v \ge 1$, write $\lfloor \log_2 v \rfloor$ zeros, then $v$ in binary. Example: 5 is \texttt{00101}. The length is
	\[ 2 \lfloor \log_2 v \rfloor + 1. \]
	\item Decode: count $z$ zeros, then read $z + 1$ bits. For $v \ge 0$ encode $v + 1$.
\end{facts}
\topic{Padding to a fixed block}
Use it when the channel stores blocks of a fixed size.
\begin{facts}
	\item Write gamma of $\mathit{len} + 1$, then the payload, then zeros up to the block size. Check that it fits.
	\item Never trim trailing zeros to find the payload: it may end in zeros.
\end{facts}
Example: payload \texttt{00} has length 2, so it is sent as \texttt{011 00} and then the padding.
\topic{Varshamov--Tenengolts: one insertion or deletion}
Use it when a block of known length $n$ may lose or gain one bit, and no bit flips.
The code words $x_1..x_n$, stored as the bit string \texttt{s} (bit \texttt{s[i]} has weight $i + 1$), satisfy
\[ \sum_{i=1}^{n} i\, x_i \equiv a \pmod{n + 1}. \]
Fix $a = 0$: that class is the largest, at least $2^n / (n + 1)$ words.
\begin{facts}
	\item Encode: positions $1, 2, 4, .. \le n$ are reserved, data fills the others, $n - \lfloor \log_2 n \rfloor - 1$ bits. Let $d \in 0..n$ be the residue still missing after the data; position $2^j$ holds bit $j$ of $d$.
	\item Length $n - 1$ (a deletion): let $w$ be the number of ones of the received $y$, and
	\[ \Delta = \Big(a - \sum_i i\, y_i\Big) \bmod (n + 1). \]
	\item If $\Delta \le w$, a 0 was lost: insert 0 with exactly $\Delta$ ones to its right. Else a 1 was lost: insert 1 with exactly $\Delta - w - 1$ zeros to its left.
	\item Length $n + 1$ (an insertion): delete each bit in turn and keep the result with residue $a$; all such results are equal. Length $n$: nothing happened.
\end{facts}
Example: \texttt{101} has residue 0 modulo 4. Deleting the middle bit gives \texttt{11}: $\Delta = 1 \le w = 2$, so insert 0 with one 1 to its right.
\topic{Complementary pairs}
Use them when block alignment survives and flips must become known erasures.
\begin{facts}
	\item Send 0 as \texttt{01} and 1 as \texttt{10}. \texttt{00} and \texttt{11} are invalid: an erasure for an outer code (\S\ref{linearcodes}).
	\item One flip in a pair is always detected. Two flips in one pair give the other valid pair, undetected.
	\item If all flips go one way ($0 \to 1$ only, or $1 \to 0$ only), every changed pair is detected.
\end{facts}
\topic{Two checksums}
Use them to find and repair one changed symbol, when the sums themselves arrive safely.
For symbols in $\mathbb{F}_p$ at positions $1..n$, $p$ a prime above $n$, send
\[ S_0 = \sum_{i=1}^{n} x_i, \qquad S_1 = \sum_{i=1}^{n} i\, x_i. \]
\begin{facts}
	\item Let $\Delta_0, \Delta_1$ be the received sums minus the sent ones. With one changed symbol, it sits at
	\[ j = \Delta_1 / \Delta_0, \]
	and its value went up by $\Delta_0$.
	\item With more changes, $j$ can be a wrong position. If $\Delta_0 = 0 \ne \Delta_1$, treat it as detected but unlocatable; do not compute $\Delta_1 / \Delta_0$. From three changes on, both $\Delta$ can be 0.
\end{facts}
Example over $\mathbb{F}_{11}$: position 3 changes from 2 to 5, so $\Delta_0 = 3$, $\Delta_1 = 9$ and $j = 3$.
\topic{Hash a candidate}
Use it when you can list a few possible originals and a trusted digest of the true one is known.
\begin{facts}
	\item Compare the length and \texttt{StrHash(s).get(1, sz(s))} (\S\ref{strhash}); characters must be 1 to 127.
	\item Across passes, replace the random base by a constant (\S\ref{multipasscheck}).
	\item A match is probable, not certain: a hash verifies, it never locates an error.
\end{facts}
}
\cpp[4]{Hamming SECDED}{hamming.hpp}[
	\fld{Use} \texttt{auto w = hammingEncode(x); ll y = hammingDecode(w);}
	\fld{Result} \texttt{y == x} after at most one flipped bit of \texttt{w}, and $-1$ after exactly two (single-error correction, double-error detection).
	\fld{Needs} $0 \le x < 2^{57}$. Three or more flips can give a wrong \texttt{y} silently.
]\label{hamming}

\subsection{Encoding}
\cpp[4]{Tree canonical form (AHU)}{ahu.hpp}[
	\fld{Use} \texttt{AHU t; vector<int> id = t.rooted(g, r);}
	\fld{Result} \texttt{id[u] == id[v]} iff the subtrees of $u$ and $v$ under root $r$ are isomorphic; ids run over $1..\texttt{sz(t.ids)}$.
	\fld{Needs} a tree on $1..n$, $n \ge 1$, each edge in both lists. \texttt{t = AHU()} clears the table.
	\fld{unrooted} \texttt{t.unrooted(g) == t.unrooted(h)} iff $g$ and $h$ are isomorphic as unrooted trees.
]\label{ahu}
\cpp[4]{Rank / unrank}{rankunrank.hpp}[
	\fld{Use} \texttt{Bigint r = rankSubset(a); a = unrankSubset(n, k, r);}
	\fld{Result} \texttt{a} is a sorted $k$-subset of $1..n$ and $0 \le r < \binom{n}{k}$, which is \texttt{rankBinom(n, k)}.
	\fld{Needs} Bigint (\S\ref{bigint}). Multisets: $\max a_i + k - 1 \le 2^{31}-1$.
	\fld{rankMultiset} \texttt{unrankMultiset(n, k, r)} inverts it on nondecreasing $k$-tuples of $1..n$; there are $\binom{n+k-1}{k}$.
	\fld{rankPerm} \texttt{unrankPerm(n, r)} inverts it on the $n!$ permutations.
]\label{rankunrank}
